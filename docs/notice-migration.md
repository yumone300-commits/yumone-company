# 기존 Notice 이전과 관리

원본 게시판 2페이지, 공개 7건. 원본 ID/URL을 키로 사용한다. 최초 등록 전 CMS 전체 9건(FAQ·자료 초안)을 조회했으며 기존 공지는 없었다. 기존 초안은 변경하지 않았다.

## 저장과 편집

- 관리 DB: https://www.notion.so/9782ab3c4915433284d642206df43857
- 제목, 발행일, 작성자, 상단고정, 표시순서, 원본ID, 원본URL, 대표이미지, 본문HTML 속성으로 관리한다.
- `본문HTML`이 있으면 서식을 보존하여 출력하며 허용 목록으로 정제한다. HTML을 수정할 때 검색용 `본문`도 함께 갱신한다. MCP를 쓸 때 HTML 속성은 인라인 코드로 입력하여 마크다운 자동 변환을 방지한다.
- `공개상태=발행`, `공개검수=true`이고 발행일이 지난 글만 공개한다. 원본ID를 변경하지 않는다.
- 대표이미지와 본문이미지는 `public/images/notices/`에 원본 바이트 그대로 저장했다. 기존 도메인에 의존하지 않는다.

## 조회 모드

- 서버에 `NOTION_TOKEN`이 있으면 CMS가 유일한 공개 상태 기준이다. 조회 실패 시 저장된 글로 대체하지 않고 오류·재시도를 표시한다. 비공개 전환한 글이 다시 노출되는 것을 막는다.
- 서버 토큰이 없으면 공지에 한해 검수된 `src/data/notice-migration.json` 게시 스냅샷을 사용한다. FAQ·자료의 미연결 상태를 정상으로 가장하지 않는다.
- 스냅샷 모드에서는 노션 수정이 자동 반영되지 않는다. 서버 토큰과 DB 접근 권한을 연결하거나, `NOTION_TOKEN`을 안전한 환경변수로 설정하고 `node scripts/support/sync-notices.mjs`를 실행한 뒤 결과를 검토·배포한다. 스크립트는 글을 새로 생성하지 않으며 중복 원본 ID와 미보존 첨부파일 발견 시 중단한다.
- 원본 HTML과 수집/검증 결과는 작업 폴더의 `notice-migration-audit`에 보관했다.

## 확인한 제한

원본 171952485의 ‘기사 보기’ 첫 앵커는 원문에 목적지가 없었다. 글과 바로 다음 실제 기사 링크는 그대로 유지했다. 임의 목적지는 추가하지 않았다. 첨부파일은 원본 7건 모두 없었다.
